`axon` is the command-line entry point to a platform run by an organisation.
You install one tool and log in once with `axon login`. Each part of the
platform is a command group of `axon`. A group that passes a tool's own
commands straight through is named for the tool: `axon sky` runs SkyPilot's
`sky` commands. A group that hides its tool behind commands of its own is named
for the part of the platform it reaches, so the tool behind it can change
without changing how you reach it.

Your organisation decides how your laptop reaches its platform. Each way in is
a **pathway**, and your organisation describes its pathways in a
**config file** that it gives you. `axon` logs in by the pathway you are
on, and names no organisation itself.

## What is built today

One command group:

| Command group | Part of the platform | Tool behind it |
|---|---|---|
| [`axon sky`](/axon/sky/) | Dev environments, GPUs, jobs and volumes | SkyPilot |

Two kinds of pathway:

| Kind | Reaches the platform | Login |
|---|---|---|
| [Direct](/axon/pathways/direct/) | At the server's own address | The server's own, in a browser |
| [Teleport](/axon/pathways/teleport/) | Through Teleport, by a tunnel that `axon` runs for you | Teleport's, in a browser when your certificate is not valid |

`axon sky` sends your commands to your organization's SkyPilot API server, with
SkyPilot's own help: wherever SkyPilot says `sky`, type `axon sky`.
`axon` installs the SkyPilot client it needs for its own use, and keeps
everything it owns on your laptop in `~/.axon`.
